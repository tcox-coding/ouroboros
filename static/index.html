What automatic runs pick from

The loop picks from this same catalog: it shortlists by description across everything installed, then compares the shortlist's example renders against your reference.

The scan below is only the fallback for setups without a classified catalog.

Add a pose

Any picture of a person in the pose you want: a screenshot, a photo, another character. Its skeleton (body, hands and face points) is extracted with DWPose and saved; only the pose is used, never the character. The LLM also writes a short description of the pose for the prompt writer and the judge. Pick it in a job's Pose selector: the character comes from the reference, the pose from here.

Judging

Every judge call starts a fresh context. Accuracy drops as a prompt grows (well before the window is full) and the middle of a long prompt is recalled worst, so the rubric, rules and reference go first, a task reminder goes last, and older rounds are folded into a short AI-written summary to stay under the budget.

Checkpoint and LoRAs

LoRAs outside these folders (such as a hand-fix LoRA) stay as saved in the workflow. The checkpoint's family (Pony, Illustrious, Flux) comes from its name; LoRAs made for another family are skipped. Flux checkpoints can't run in this SDXL workflow. The Civitai key is under API keys above.

Pose ControlNet and hand refiner

Both use the xinsir ControlNet Union (SDXL) in openpose mode. HandRefiner's own ControlNet is SD 1.5 only and can't attach to an SDXL checkpoint, so hands are refined the same way natively: DWPose fits each hand with a clean five-finger skeleton, and just that hand is repainted at 1024 px following it. The automatic pass keeps the refined image only if a fresh judge look scores it at least as high; the button on a finished run always keeps both.
